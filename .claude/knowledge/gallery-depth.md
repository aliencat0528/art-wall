# 長廊景深與展場漫步 — Phase F／G 提案與實現限制

> **載入時機**：討論 Phase F（長廊景深）、Phase G（展場漫步彩蛋）、或任何
> 「作品牆要更有展場感」的視覺提案時。
> **狀態**：提案，方向未定（見 `prepare.md` 待討論事項 #2）。定案後轉 `MR-014`，本檔改記落地細節。

---

## 起點

2026-07-24 用戶提出一張參考圖：第一人稱視角的展場走廊，作品掛在左右牆上沿透視後退，
畫面有消失點與地板網格，左上角資訊面板寫 `ON VIEW` + 襯線斜體作品名 + 等寬小字說明
（媒材／尺寸／年份），底部是 `← BACK` / `WALK ON →`，提示 `ARROW KEYS TO WALK`。

這不是新方向——`prepare.md` 的 Phase 重排已經排了 **Phase F（長廊景深＋詳情頁 pan/zoom，
純視圖層）** 與 **Phase G（展場漫步彩蛋，須待 E／F 穩定）**。本檔是把那兩格填上內容。

---

## 關鍵拆解：質感有八成不來自 3D

把參考圖的元素逐項歸因，會發現多數「高級感」是平面設計給的：

| 元素 | 來源 | 需要 3D？ |
|------|------|-----------|
| 襯線斜體作品名 | 字體搭配 | ✗ |
| `ON VIEW` 紅色小標、等寬大寫說明 | 排版層級 | ✗ |
| 白邊裱框（mat + 細框） | `border` / `padding` | ✗ |
| 作品浮離牆面的投影 | `box-shadow` | ✗ |
| 牆面展籤（作品名等寬大寫置中於卡片下方） | 一行文字 | ✗ |
| 左側大色塊疊印的資訊面板 | `mix-blend-mode` | ✗ |
| 消失點透視、可以走進去 | CSS 3D transform | ✓ |
| `ARROW KEYS TO WALK` / `WALK ON` | 場景狀態機 | ✓ |

**這個歸因直接決定投報率**：前六項沒有任何一條會踩到下方的限制，最後兩項則是全部限制的來源。

---

## Phase G 的技術路徑（若要做第一人稱）

不需要 Three.js 或任何 3D 函式庫，純 CSS 3D 即可：

- 場景容器 `perspective`，左右牆 `rotateY(±90deg)`，地板 `rotateX(90deg)`
- 每件作品是**普通 DOM 元素**，只是 `translateZ(-n × 間距)` 掛在牆上
  → 圖片、點擊、無障礙樹、IndexedDB 取圖全部沿用現況，不需為 3D 另建一套
- 「走」＝改場景上的一個 CSS 變數（相機 Z）並補間
- **離散步進**（一次一件，配 `BACK` / `WALK ON`）而非自由漫遊——參考圖本身就是這個設計，
  也剛好避開自製遊戲引擎的坑

---

## 實現限制（做 Phase G 前必須先接受這幾條）

**1. Safari 的 `preserve-3d` 遇祖先 `overflow` 會整個壓平**
現有長廊 `WorkRail.vue:161-164` 是 `overflow-x: auto` + `scroll-snap`，天生帶 overflow。
→ 走廊**不能疊進現有長廊**，必須是獨立的第三種瀏覽模式。

**2. 手機基本上不成立**
`<900px` 現在走網格（`ARCHITECTURE.md` 版面尺寸表）。第一人稱在手機視野裡一次只看得到一件，
等於退化成 slideshow。MR-008 已因近似理由棄選過平板兩欄。
→ 要嘛手機退回網格（多維護一套模式），要嘛接受手機體驗明顯變差。

**3. 30 秒法則——最硬的一條**
第一人稱代表訪客**必須走**才看得到第 5 件作品，招募端不會走。MR-001 的結論是
「遊戲層必須是加分而非路障」。
→ 走廊只能是第三顆模式鈕（依媒材／依展覽／走進展場），**不可為預設入口**。
這正是 `prepare.md` 把它定為「Phase G 彩蛋」而非主線的原因。

**4. 近景圖片會糊**
`utils/image.ts` 的 `THUMB_MAX_EDGE = 800`、`VIEW_MAX_EDGE = 1800`（MR-009）。
走廊裡最近那件會佔到半個畫面寬，800px 撐不住。
→ 近景改抓 1800px 那張（多一次大圖載入），或接受略糊。這是實打實的成本。

**5. `prefers-reduced-motion` 下走廊沒有意義**
走廊的價值全在位移補間。開了減少動態就該**直接不提供**這個模式，
而不是給一個瞬移版本（`main.css:100` 已關掉全站動畫與轉場）。

**6. 襯線字是唯一的新依賴風險**
`main.css:34-35` 目前只有 `--font-sans` / `--font-mono`，全系統字、零 `@font-face`。
加襯線要嘛用系統襯線（各平台長相不一），要嘛自帶 web font（100–200KB 首屏成本）。

**7. 好消息：不動資料層**
沿用現有 `filteredWorks`；`aspect-ratio` 那套版位邏輯在 3D 下依然成立
（transform 不改 layout box，`ARCHITECTURE.md` 的「版面尺寸唯一真相」不受影響）。
且**展覽動線放進走廊特別合理**——策展本就是有序的（MR-012 ①），走廊即那條動線的具象化。

**Phase F 先做，不含第一人稱**：裱框白邊、牆面投影、展籤、`ON VIEW` 標籤、襯線標題、
卡片沿 Z 軸微幅後退的景深。上述七條限制**一條都不會踩到**——不動 overflow、手機照樣網格、

**Phase G 再做真走廊**，作為第三種瀏覽模式，帶著限制 1–6 去設計。

## 四條討論軸與各自的既有約束

用戶（2026-07-24）把訴求歸納為「設計感、視覺感、色彩感、立體感，希望有藝術空間的畫面與空間感」。
四條軸的自由度**差很多**——有兩條幾乎沒有包袱，另外兩條會直接撞到已定案的決策。
下次討論不該平均分配時間，而該集中在後兩條。

### 1. 設計感／視覺感 — 自由度高，直接做

現況已定的只有骨架：開場 3.4 秒幾何動畫、分類切換換 accent＋動效曲線＋卡片邊緣＋背景紋理（MR-008）。
裱框、投影、展籤、`ON VIEW` 標籤、排版層級這些**都還是空白**，沒有任何決策卡住。
→ 這是投報率最高的一段，屬 Phase F，可直接提案。

### 2. 空間感 — 自由度高，且不必等 3D

「藝術空間」的感覺主要來自牆面／地板的界定、光線落點、作品浮離牆面的陰影、展籤的存在，
**這些在平面版型裡就做得出來**。不要把「空間感」自動等同於「要做 3D」——
參考圖的空間說服力有相當比例來自陰影與留白，而非透視本身。

### 3. 色彩感 — ⚠️ 與根定調直接衝突，必須先討論

**這是四條裡最需要決策的一條。** 現有定調是一路往「中性」收斂的：

- D-003：外殼**中性白盒**，理由是「強風格單色濾鏡會吃掉作品顏色」
- MR-008 棄選「整站隨分類換皮」，理由是「等於維護 4 套設計系統，**且吃作品顏色**」
- MR-008：背景紋理**灰階、不透明度 ≤3%**
- MR-009：整體背景四選一（白盒／暖紙／清水模／暗展廳），與分類主題正交

而參考圖左上角是**大面積紅／深藍疊印色塊**壓在資訊面板上——那是強烈的色彩宣示，
與「中性襯托作品」是**方向相反**的。

不是不能做，但要想清楚這是哪一種：

| 選項 | 說明 | 代價 |
|------|------|------|
| A. 維持中性，色彩只出現在 UI 邊角 | 現行 accent 貫穿站頭底線／卡片外框／進度條的做法再往前一點 | 拿不到參考圖那種氣勢 |
| B. 色彩區塊限定在「非作品區」 | 資訊面板、開場、展覽前言可以濃，作品牆面維持中性 | 兩套語彙要能共存不打架 |
| C. 推翻中性定調 | 真的走參考圖路線 | 需覆蓋 D-003／MR-008，且作品顏色會被吃掉——這是當初棄選的原因 |

→ **建議 B**：它讓色彩有地方發揮，又保住「作品是主角」這條底線。但這需要一筆新決策拍板。

### 4. 立體感 — 見本檔前半

七條限制都在前面。重點是「立體感」可以只做到 Phase F 的景深（無限制），
不一定要走到 Phase G 的第一人稱（七條限制全上）。

## 各方案的變更歷程（都是實測後才發現的）

**E 的網點，兩次收斂到全數移除**
1. 初版依 halftone 參考圖鋪滿三層方點 → 太吵，顆粒變成壁紙、把作品壓下去
2. 背景改線框展場，網點退守色帶與框線 → **仍然太花**。根因是線框地板本身
   已經是一套密集的重複圖案，再疊網點等於同一畫面有兩套重複紋理互相打架
3. 網點完全移除：色帶改純色、作品改無框（襯紙＋側面厚度＋投影已足以界定邊界）

→ **可複用的結論：一個畫面只能有一套重複圖案。** 空間感與紋理感二選一，
不要同時給。E 最後把視覺重量全押在空間，表面一律留白。

## 色彩建議

**核心主張：把「中性」重新定義為「無彩」，而不是「低對比」。**

現況呆板的原因不是沒有顏色，是**結構沒有對比**——實測 `white-cube` 的
`--line #dedbd4` 對 `--bg #f7f6f3` 只有 **1.28:1**，結構線幾乎看不見。
而作品是有彩的、外殼是無彩的，兩者靠**彩度**分開就夠，不必靠明度。
所以外殼的明度對比可以放心拉到最大，完全不會吃作品顏色。

E 採用的骨架，對比實測：

| 角色 | 值 | 對紙底的對比 |
|------|-----|------------|
| 紙底 | `#d6d3ca`（暖灰，比白盒暗一階） | — |
| 墨（字、標題） | `#141310` | **12.6:1** |
| 襯紙（作品襯底） | `#e6e3da` | 亮於紙底，作品浮起來 |
| accent | 分類色，面積 ≤ 15% | 唯一的彩度來源 |

順帶一提：紙底比純白暗一階還有一個實際好處——**作品裡的白會亮出來**。
白底會把作品的白邊吃掉，這也是實體美術館少用純白牆的原因。

**⚠️ 若走無彩骨架（E／F），內建六類有兩個 accent 會失效**

`書法 #3d3a35` 與 `立體 #6b6355` 幾乎無彩（HSL 彩度極低）。在無彩骨架上它們
與骨架分不開——實測 E 切到書法時，整條色帶變成一塊死掉的深灰板，F 切過去也一樣沒有光色。
→ 這兩類需要改為有彩，且有現成的合理依據（材料自身的顏色）：
書法 → 印泥朱紅、立體 → 陶土赭。**這是採用 E／F 的前置條件，不是可選項。**

## 立體效果的完整階梯（由便宜到昂貴）

用戶問「立體效果你能如何呈現」。以下依成本排序，並標註是否踩到本檔前半的七條限制。

**已做進 E／F（零限制）**
1. **浮離投影** — `box-shadow`，作品離開牆面。歸因表裡投報率最高的一條
2. **襯紙裱框** — 作品不直接貼牆，有物理層次
3. **透視線框地板** — `rotateX(74deg)` 的網格，線距自然收斂到消失點。**用戶明確認可這條**
4. **卡片透視傾斜** — 左右欄各朝內轉 3.2 度、中欄正對，等於站在展場中央的視點
5. **游標視差** — 背景位移 18px、作品僅偏轉 1.4 度。**差速才是深度的來源**，不是位移量本身
6. **光影隨傾斜換邊** — 光影不連動的話，大腦會讀成「圖被壓歪」而不是「板子轉了角度」
7. **畫框側面厚度** — 傾斜背向的那一側露出實邊
8. **地面倒影**（F） — `scaleY(-1)` + `translateY(-100%)` 翻回原位再淡出。
   同時給出「作品離地多高」與「地面在哪」，是暗場裡最強的立體線索

**還沒做、但仍屬 Phase F（零限制）**
9. **捲動視差** — 地板與牆面以不同速率位移
10. **側牆** — 畫面兩側各一道 `rotateY` 的牆把長廊框起來（站在入口看，不是走進去）。
    效果強但會壓縮版面可用寬度

**要到 Phase G（七條限制全上）**
11. 第一人稱走廊：消失點、方向鍵行走

→ **9 之前的都不必等 Phase G。**「立體感」不等於「要做 3D 場景」——
第 1、5、6、8 這四條加起來的說服力，比單獨做透視高得多。

## 目前建議

1. **E 與 F 是同一個骨架的兩種光**（無彩結構 + 彩度只給作品與 accent），
   差別只在明場／暗場。兩者可以是同一套設計的日／夜模式，不必二選一——
   這剛好對上 MR-009 已經存在的「整體背景四選一」機制
2. 色彩檔位選 **B**：不需要覆蓋 D-003／MR-008。F 的暗場推翻的是「白盒」，
   不是「中性」——暗展廳本來就是美術館做法
3. 採用前必須先解掉書法／立體兩個 accent 無彩的問題
4. 一個畫面只放一套重複圖案（E 的兩次收斂換來的教訓）
